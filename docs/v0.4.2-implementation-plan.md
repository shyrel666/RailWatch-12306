# RailWatch 12306 v0.4.2 实施计划

日期：2026-09-22
状态：M0–M3 的代码与自动化验证完成；M4、M5 已实施并通过离线回归，M4 的同名乘客稳定身份区分仍待真实页面证据；M6 集成打包与人工验收进行中。已完成任务以勾选项和阶段验证记录为准。

## 1. 版本目标与范围

目标：用户能准确配置行程、辨认查询结果、在后台等待提醒，并理解订单状态与下一步操作。

用户已确认：本版包含七项核心改进；行程模板、时间段／耗时筛选、多行程任务队列、一键诊断报告列为后续版本候选。

| 编号 | 本版交付 | 优先级 | 完成标志 |
| --- | --- | --- | --- |
| C1 | 结构化查询结果与数据时效 | P0 | 按日期、区间、席别展示结果，状态不再从整行文字猜测 |
| C2 | 托盘、退出与更新保护 | P0 | 关闭窗口的行为可预期，退出与更新不会静默中断活动任务 |
| C3 | 可配置、可验证的通知 | P1 | 三种外部渠道可配置和测试，声音、桌面通知与置顶设置实际生效 |
| C4 | 站名联想、实际车次选择与收藏 | P1 | 用户从当前路线的查询结果选择目标，固定示例车次被个人收藏替代 |
| C5 | 席别与乘客配置完善 | P1 | 展示经过验证的席别，乘客信息不再无条件标为成人，自动化支持边界明确 |
| C6 | 草稿、保存状态与启动摘要 | P1 | 可恢复草稿，知道哪些修改已保存，启动时能核对本次执行条件 |
| C7 | 订单中心与核对时间线 | P1 | 可查看历史、详情、核对时间和观察状态，继续处理已有订单 |

P0 决定实施先后；C1–C7 都是本版交付项，不因标为 P1 而默认省略。

M0 已完成公共契约与兼容基础。正式版本号、变更日志归档、安装包及发布说明在功能验收后统一处理。

## 2. 当前基线与实施约束

- 当前项目版本为 0.4.1。实施前记录工作区差异，保留用户已有修改。
- 当前 `CHANGELOG.md` 的 Unreleased 已包含订单证据、DPAPI 异常恢复和原子写入清理修复；这些修复应随 0.4.2 一并回归与交付，不能在本轮重构中丢失。
- Python 桥接层继续作为购票任务与订单状态的权威来源；Electron 管理窗口生命周期与桌面提醒；React 展示状态并提交用户操作。
- 保留任务配置快照、浏览器串行访问、未知提交不重放、订单证据核对及未完成订单互斥。
- 本版仍为单个活动购票任务。车次多选、个人收藏和多日期结果不等于多个任务并行执行。
- 自动提交与自动候补默认关闭；草稿恢复、收藏应用、版本升级都不得自动开始交易。
- 新增 IPC 命令同步覆盖白名单、preload／类型声明、Python 分发和桥接实现；所有标识符、分页参数和用户输入在后端校验。
- 新增功能采用增量数据结构；旧数据缺字段时提供明确的兼容展示，不伪造成功状态、查询时间或乘客票种。
- 本地单元测试和浏览器夹具不代表真实账号购票验收。实际核验与支付继续由用户在官方页面完成。

## 5. M1／C1：结构化结果与时效

实施前：`railwatch_row_parser.py` 已有席别快照，但 `display_rows()` 只传出车次和原始文本；`MonitorPage.tsx` 用整行关键字设置状态；store 没有保留查询时间及条件。

涉及：`railwatch_row_parser.py`、`railwatch_query.py`、`gui_12306_0.py`、`railwatch_bridge.py`、`src/types.ts`、`src/store/railwatchStore.ts`、`src/components/MonitorPage.tsx`。

- [x] 从已读取的 DOM 快照生成可序列化结果：车次、查询日期、实际区间、可读取的出发／到达时间、各席别状态与数量、原始文字。
- [x] 区分席别状态：有票、无票、可候补、未知、不适用。数字数量只由席别单元格解析；`raw` 用于展开详情，不参与有票判断。
- [x] 统一手动查询与监控事件的 `run_id`、`query_id`、条件快照和 `fetched_at`；每个日期的结果保留各自采集时间。
- [x] 多日期结果按路线、日期及车次保存，不因下一个日期轮询而将其混为同一批结果；条件变更时清理或隔离旧条件数据。
- [x] 展示用户选中席别与明确的列标题，不只依赖颜色区分状态。
- [x] 展示最后成功查询时间、当前查询日期和运行／停止状态。查询失败时保留上一份结果并标记“上次成功结果”；过期判断结合下次查询计划、超时和退避状态。
- [x] 缺少结构化字段的兼容数据展示“状态未知”，不从旧原始文本补猜状态。

关键验收：数字余票能正确展示；站名含“张”和席别名“无座”不触发错误状态；不同席别有票／无票混合时正确显示；同车次不同日期可区分；空结果能清除对应日期旧数据；迟到事件不覆盖新任务；断网、退避和停止后的旧结果不会伪装为实时数据。

完成记录（2026-09-22）：Python 258 项、Electron 40 项、React 133 项测试通过；离线查询浏览器 22 项、订单浏览器 34 项通过；类型检查、生产构建和明暗主题／双窗口尺寸 UI 冒烟通过。实现、时效规则及验证边界见 [v0.4.2-m1-validation.md](v0.4.2-m1-validation.md)。

## 6. M2／C2：托盘、退出与更新保护

现状：`electron/main.ts` 在所有窗口关闭后停止运行时；安装更新入口只检查是否下载完成。隐藏的声音窗口也会影响窗口计数，不能仅靠 `window-all-closed` 判定用户已退出。

涉及：`electron/main.ts`、`electron/pythonRuntime.ts`、`electron/updateManager.ts`、`electron/alertManager.ts`、`electron/confirmationBridge.ts`、`src/lib/useThemedDialogs.ts`、设置页；建议拆分生命周期管理模块。

- [x] 增加“关闭到托盘”偏好。启用后，主窗口关闭仅隐藏，托盘显示当前状态，并提供显示窗口、停止监控和退出入口。
- [x] 首次关闭时清楚说明后台行为；托盘创建失败时保留可见窗口或进入正常退出确认，避免应用无法找回。
- [x] 建立统一退出状态机：阻止新任务进入、请求停止、等待退出／刷写结果、停止运行时、清理声音窗口和托盘。
- [x] 用户退出时，根据活动任务和未完成订单显示具体影响；未完成订单允许在提示后保留记录退出，不把本地退出解释为取消官方订单。
- [x] 后端提供权威的退出／更新准备检查，覆盖查询初始化、监控、提交、核对、停止中及其他占用浏览器的操作；与新任务准入保持互斥，避免检查通过后立即启动新任务。
- [x] 更新提示不在交易处理中打断操作；主进程安装入口再次校验。检查并纳入 `autoInstallOnAppQuit` 路径，防止绕过统一门禁。
- [x] 本版策略：活动任务和未完成订单存在时推迟安装；普通退出保留订单。运行时状态未知时拒绝自动安装并说明原因。
- [x] 处理正常停止超时、运行时崩溃、二次退出请求和系统关机；无法延缓的关机依靠已落库意图恢复，不声称可以阻止所有系统终止。

关键验收：定时等待时关闭到托盘仍继续等待；再次启动应用恢复原窗口；取消退出不停止任务；真正退出无本应用运行时残留；提交／核对中安装更新被拦截；用户确认停止后不会产生后续重复提交；重启能恢复原订单。

代码、自动化验证及尚待安装包核验的边界见 [v0.4.2-m2-validation.md](v0.4.2-m2-validation.md)。

## 12. 数据、升级与兼容策略

- 偏好文件采用字段增量更新，保留未知字段；草稿、路线收藏和通知凭据按用途分开保存，避免覆盖既有配置。
- 查询结果是运行态数据，本版不新增完整余票历史数据库；跨重启的恢复重点是配置、草稿与订单。
- 配置 schema 版本与应用版本独立；是否增加 schema 版本由最终乘客结构决定，在 M0 固定迁移规则。
- 若增加数据库字段，采用事务和显式 schema 版本迁移；升级失败给出可恢复错误，不能重建或清空未完成订单。
- 从 0.4.1 升级时保留已有配置、主题、通知密钥与订单记录；托盘及新增通知字段使用明示默认值。
- 自动化开关即使来自已保存配置，启动时仍需现有授权流程；恢复记录绝不等同于允许重放未知提交。
- 使用临时用户目录验证升级，禁止用真实 Chrome 会话或生产订单库做自动测试夹具。

## 13. 验收与发布条件

### 必测用户路径

| 场景 | 验收结果 |
| --- | --- |
| 首次使用 → 检查环境 → 登录 → 配置 → 查询 → 启动 | 每一步都有明确状态与下一步操作 |
| 多日期查询 → 部分成功 → 网络失败 | 各日期及其结果时间明确，旧结果被标记 |
| 定时监控 → 关闭到托盘 → 需要处理提醒 | 任务保持运行，用户能从提醒或托盘返回 |
| 正在提交 → 请求退出／安装更新 | 统一门禁生效，已有意图持久化且不重放 |
| 修改配置 → 自动保存草稿 → 重启 | 草稿可恢复且不会自动启动交易 |
| 外部通知失败／凭据不可解密 | 展示失败，购票与订单恢复不被拖垮 |
| 旧订单 → 重启恢复 → 官方证据核对 | 原订单身份一致，历史与当前状态不矛盾 |
| 候补生效 → 停止本地观察 | 明确提示非持续监控，提供主动核对入口 |
