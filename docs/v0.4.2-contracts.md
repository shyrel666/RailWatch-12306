# v0.4.2 公共契约与迁移规则（M0／M1）

日期：2026-09-22。配套实施计划：`docs/v0.4.2-implementation-plan.md`。

## 1. 实现状态与版本

| 契约 | 类型／实现位置 | 当前实际行为 | 接入阶段 |
| --- | --- | --- | --- |
| 偏好局部更新 | `src/types.ts`、`railwatch_bridge.py`、`railwatch_preferences.py` | 已接入现有 `loadPreferences`／`savePreferences` | M0；新开关执行逻辑在 M2／M3 |
| 结构化查询快照 | `QuerySnapshot`、`StructuredQueryResultRow`、`QueryAttempt` | 手动／监控查询已接入；按日期保留成功数据和最新尝试 | M1 已完成 |

应用版本暂为 0.4.1；行程 `config_version` 保持 2。新查询快照和草稿各使用独立 `schema_version: 1`，不能用应用版本推测文件结构。

## 2. 通用约定

- 时间戳为 Unix **秒**，可包含小数；前端 `Date` 使用前乘以 1000。行程日期固定 `YYYY-MM-DD`，按北京时间解释。
- 持久化修订号、事件序号为非负安全整数，上限 `2^53 - 1`；不接受布尔值冒充整数。
- 对象中的可选字段缺失表示旧生产者未提供，不能默认成成功、已完成核对或无活动任务。新快照中未知值使用 `null`。
- `run_id` 标识运行任务，`query_id` 标识单次查询；任务内的序号负责排序，随机 ID 不用于比较新旧。
- 公共对象不包含 WebElement、完整证件号、Chrome 会话或通知密钥明文。原始页面文字仅用于详情展示，不用于界面有票判断。
- 尚未接入阶段的类型仅用于约束后续实现；不能据此假定 Python 已发出相关字段。

## 3. 偏好更新：本阶段已接入

### 命令与返回

`loadPreferences` 返回主题、托盘偏好和脱敏通知设置。`savePreferences` 接收 `PreferencesPatch`，成功后返回同一完整公共对象。

```json
{
  "theme": "dark",
  "close_to_tray": false,
  "notification_settings": {
    "desktop_urgent": true,
    "sound_loop": false,
    "window_attention": true,
    "server_chan_enabled": false,
    "server_chan_key": "",
    "server_chan_key_configured": false,
    "email_enabled": false,
    "email_smtp_host": "",
    "email_smtp_port": 465,
    "email_user": "",
    "email_password": "",
    "email_password_configured": false,
    "email_to": "",
    "wecom_webhook_enabled": false,
    "wecom_webhook_url": "",
    "wecom_webhook_url_configured": false
  }
}
```

局部更新示例：

```json
{"notification_settings": {"sound_loop": false}}
```

以上请求只改变通知字段，主题和托盘偏好保持原值。空对象请求不写文件。省略顶层字段表示不修改；运行时兼容顶层 `null` 为省略，新调用方应省略不修改的字段。

主题只接受 `system`、`light`、`dark`，托盘字段只接受布尔值；通知补丁必须为对象。通知字段的旧布尔值规范化行为继续兼容，M3 再补齐渠道表单及端到端参数校验。

### 密钥语义

仅对 `server_chan_key`、`email_password`、`wecom_webhook_url` 使用以下规则：

| 输入 | 含义 |
| --- | --- |
| 省略 | 保持原值 |
| `""` | 脱敏占位，保持原值 |
| 非空字符串 | 替换密钥 |
| `null` | 显式清除密钥 |
| `*_configured` | 只读元数据；旧客户端回传时忽略 |

Windows 持久化继续使用当前用户 DPAPI；返回值始终置空密钥并附配置状态。已有凭据损坏／迁移失败时保留原文件、禁用外部通知并记录告警，订单恢复不受影响。

### 默认值、存储与并发

- `ui_preferences.json`：主题、`close_to_tray`。托盘缺省为 `false`，维持旧版关闭语义直到 M2 实现关闭策略。修改时保留未知顶层字段，返回时只暴露已知 UI 字段。
- `notification_settings.json`：现有通知设置及 `window_attention`。新增置顶偏好缺省为 `true`，对应旧版行为；M3 才接入提醒执行。
- 同一进程中的 UI 偏好读改写、通知迁移／保存、活动通知设置更新使用 `PREFERENCES_LOCK`，锁覆盖完整合并过程。
- 同一运行时中，并发的不重叠补丁都保留；相同字段以锁内实际提交顺序为准。原子替换成功后才更新活动通知设置。
- 当前保证针对单 Electron 实例、单 Python bridge 的运行模型；此锁不提供多进程配置事务，也不支持多个 bridge 实例同时维护同一目录的通知缓存。
- 两个 JSON 文件分别原子提交，不构成跨文件事务。混合请求先提交通知，再提交 UI；通知加密失败不会改变主题。若通知已保存但 UI 写入失败，请求返回错误，调用方应重新加载确认各项实际状态。
- 设置页后续按设置域发送补丁，避免不必要的跨文件更新；对混合更新失败不能显示“全部未保存”或“全部保存成功”。

## 4. 查询快照：M1 接入

每个查询日期有独立 `QuerySnapshot`：

| 字段 | 定义 |
| --- | --- |
| `schema_version` | 固定为 1 |
| `run_id` | 监控任务 ID；手动查询为 `null` |
| `query_id` | 本次查询唯一 ID |
| `sequence` | 同一查询所有者内递增序号；发起时分配，不能按响应到达顺序生成 |
| `conditions` | 出发站、到达站、日期、目标车次顺序和席别顺序 |
| `completed_at` | 本次请求完成／失败时间 |
| `fetched_at` | 成功读取对应结果的时间；本次失败为 `null` |
| `status` | `success` 或 `error` |
| `error` | 失败说明；成功为 `null` |
| `rows` | 本次成功结果；成功无车次和失败均可为空，使用 `status` 区分 |

`conditions` 使用明确业务字段，不直接沿用旧 `QueryExecutor` 中包含 DOM 值数组的内部快照。旧 `conditions` 字段暂保留原行为，新业务条件位于新快照内。

行字段包括 `train`、`date`、`from_station`、`to_station`、`departure_time`、`arrival_time`、`arrival_day_offset`、`seats`、`raw`。日期来自实际本次查询；区间和时间来自可验证页面字段。时刻使用页面可验证的 `HH:mm`，跨日偏移无法读取时为 `null`，不从时刻大小推测到达日。

每个席别值为 `{status, count, raw}`：

- `available`：有票；明确数字数量可写 `count`，只有“有”时为 `null`。
- `unavailable`：明确无票；`count` 可为 0。
- `alternate`：明确支持候补；数量通常为 `null`。
- `unknown`：缺少可信字段或无法解析；数量为 `null`。
- `not_applicable`：明确不提供该席别；数量为 `null`。无法区分时使用 `unknown`。

手动多日查询通过 `ResultsPayload.snapshots` 返回多个快照；监控轮询通过 `MonitorTickPayload.snapshot` 返回当日快照。过渡期保留旧 `rows`，旧渲染器可继续显示原始信息。

M1 已接入 `queryStarted: QueryAttempt`，携带 `run_id`、`query_id`、`sequence`、业务 `conditions` 和 `started_at`，用于显示正在查询的日期。查询完成／失败后按同一 ID 收尾。此事件不改变 IPC 命令白名单。

`analyzeQuery` 接收可选 `request_id`（1–128 个英文字母、数字、下划线或连字符）；旧调用方省略时由后端生成。手动查询的 `queryStarted` 和 `results` 均回传该 ID，单日期 `query_id` 为 `request_id:sequence`。界面在发送前建立所有者，超时、条件变更或新请求会使旧响应失效；随机 ID 仅用于相等比较，不用于排序。

席别缺失或 `--`、`*` 使用 `unknown`；只有明确“不适用”才使用 `not_applicable`。实际区间必须读取到两个可见站名字段，时间必须读取到两个 `HH:mm` 字段；到达日只映射明确的当日／次日／第三日／第四日标签。

M1 store 按查询条件／日期隔离数据，保留最后成功结果和最后尝试状态。失败不能清除成功时间并假装刷新成功；成功空列表必须清除对应日期的旧行。旧任务、旧序号及旧条件响应应被拒绝；无任务 ID 的手动查询由独立请求所有者隔离。

界面过期阈值为日期范围天数 ×（查询超时 + 配置间隔）+ 5 秒。超出阈值标记过期；阈值内若 `next_query_at` 尚未到达则显示等待。服务端退避不会延长旧数据的有效期，失败／暂停／停止各自明确标记；所有保留值均称为最近或上次成功结果。此阈值用于显示数据年龄，不承诺余票保持不变。

## 5. 草稿：M0 校验，M4 保存／恢复

文件为 `trip_draft.json`，独立于正式行程配置：

```json
{
  "schema_version": 1,
  "revision": 7,
  "saved_at": 1780000000.5,
  "config": {"from_station_cn": "", "date": "2000-01-01", "auto_submit": false}
}
```

- `revision` 为全局于这份草稿的持久化安全整数；M4 启动写入前读取已有修订并递增，后端拒绝旧修订覆盖新修订。
- `saved_at` 为后端完成持久化时记录的时间；M0 校验其有限、非负且在 JavaScript 安全数值范围内。
- 草稿允许字段不完整、过期日期和编辑中的日期字符串，校验字段类型但不运行正式出行日期窗口校验，也不补默认行程。
- 已知行程字段遵循现有类型；若携带 `config_version`，当前只接受 2。未知 JSON 字段保留，执行时仍需走正式配置校验。
- 不把读取或恢复草稿视为启动授权；即使草稿带有自动化开关，M4 启动仍需既有校验和确认。
- `load_trip_draft()` 只返回 `available`、`missing`、`invalid`。损坏、未来版本及不可读文件统一返回带说明的 `invalid`，保留原文件；正式配置和订单库不参与此回退。
- M0 不调用自动保存、不注册草稿 IPC，也不在启动时自动将草稿应用到表单。M4 才接入 UI 和退出前写入收尾。

## 6. 任务活动状态：M2 接入

`TaskActivity` 定义 `state: idle | busy | unknown`、`run_id`、`operation`、`unresolved_order` 和 `checked_at`。

- `busy` 覆盖初始化、查询、等待起售、提交、核对、停止中及其他占用受控浏览器的操作，不只看前端 `monitoring`。
- `idle` 仅表示无活动浏览器任务；如果 `unresolved_order=true`，仍不能据此自动安装更新。
- 运行时中断／权威状态不可用时为 `unknown`；不能把旧快照的 `idle` 当作当前状态。
- 当前观察快照不代表拥有退出／更新权限。M2 必须在后端锁内检查任务、阻止新任务进入并进入停止流程，主进程最终安装前再次确认结果。
- 不改变当前 `task.status` 与订单状态机枚举；新增 `activity` 在旧生产者中允许缺失。

## 7. 订单摘要与时间线：M5 接入

列表类型为 `OrderHistoryPage {items, next_cursor}`；详情为 `OrderHistoryDetail {summary, events, history_complete}`。M5 新增接口时使用有界分页、后端校验的游标和参数化查询。

`OrderHistorySummary` 包含订单意图 ID、可用的官方订单号、类型、车次、日期、区间、席别，并明确区分：

| 字段 | 含义 |
| --- | --- |
| `status` | 本地最近处理／核对结果，可以是 unknown、verification 或 dismissed |
| `official_status` | 最近有匹配官方证据确认的状态；没有则为 `null` |
| `official_verified_at` | 上述官方状态确认时间；没有可靠记录则为 `null` |
| `updated_at` | 本地订单记录更新时间，不能替代官方核对时间 |
| `last_checked_at` | 最近一次实际页面核对完成时间；核对结果可能仍未知 |
| `observing` | 当前是否有本地观察任务；不等同于官方候补是否生效 |
| `recovery_required` | 是否需要继续核对／恢复 |

时间线事件包含 `sequence`、`at`、`stage`、`scope: local | official` 与脱敏 `message`。点击提交、结束本地核对属于本地事件；只有匹配页面证据的状态才标记官方事件。未知回读可以更新本地核对结果，但不能覆盖为虚构的官方成功。

缺少历史事件时 `history_complete=false`；不得使用最新 `updated_at` 补造历史时间。M5 如需增加字段或索引，应以事务进行增量迁移，保留现有意图、证据与未完成订单互斥。

## 8. 旧数据迁移决策

| 旧数据 | M0 行为 | 后续约束 |
| --- | --- | --- |
| 无新增字段的行程配置 | 沿用 v2 补默认值，自动化缺省关闭 | 保留原日期，不自动顺延 |
| 已过期日期 | 可加载、可保存；执行时按窗口筛选 | 启动摘要展示实际有效日期 |
| 主题文件缺托盘字段 | 返回 `close_to_tray=false` | M2 再呈现选项 |
| 通知文件缺置顶字段 | 返回 `window_attention=true` | M3 才让执行逻辑消费该值 |
| 通知凭据不可解密／迁移失败 | 禁用外部通知、保留原文件与订单恢复 | 仅用户重新配置时替换相应凭据 |
| 草稿不存在／损坏／版本未知 | missing／invalid，独立于正式配置 | 不覆盖正式配置、不自动启动 |
| 已有未完成订单 | 沿用原订单恢复与新交易阻止逻辑 | 任何草稿或偏好迁移不改变订单状态 |
| 未知偏好字段 | UI 文件原样保留，不全部透传渲染进程 | 后续明确支持后再公开 |

行程 schema 本版按“v2 保留现有字段语义、新字段可选”的方向演进。若 M4 乘客结构必须改变现有字段的类型或执行含义，则单独增加 schema 版本并补迁移，不将本契约视为授权静默重解释旧值。
