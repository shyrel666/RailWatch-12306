# v0.4.2 M5 订单中心验证记录

日期：2026-09-23。范围：C7 历史、详情、核对时间线和继续处理原订单。

2026-09-28 补充：修复后的订单读取逻辑已在真实待支付页面取得单号，并与保存的完整行程及乘客名单匹配。此次只读检查没有更新运行中应用的订单记录；界面同步、支付后状态、候补及异常恢复仍待完整真实场景验收。下文保留 09-23 阶段记录，最新范围见 [可靠性记录](transaction-reliability.md)。

## 已实现

- 基于现有 `orders` 与 `order_events` 表提供有界分页、状态筛选和只读详情；分页参数验证后使用参数化 SQL。每个订单结果即时写入事件，查询遥测仍按原批处理和裁剪策略运行。
- 列表和详情分别呈现官方证据确认状态、本地核对结果、当前观察状态及已知核对时间。旧记录缺少事件时显示历史不完整；未知结果不会据此晋升为官方成功。
- 继续处理入口复用现有浏览器互斥与原订单身份核对；结束本地核对明确不代表取消官方订单。已生效候补显示当前没有周期性自动复查。
- 导航增加订单中心，仪表盘提供入口，页面在窄窗口仍可阅读。

## 验证证据

`tests/test_m5_order_history.py`、`tests/test_orders.py`、`OrderCenterPage.test.tsx` 覆盖分页、事件、旧记录、继续核对与状态呈现。`tests/trip_order_ui_smoke.py` 用本地模拟数据检查双尺寸列表与详情。订单恢复、官方页面证据和未知提交不重放由原有订单回归及 `tests/order_browser_smoke.py` 覆盖。完整回归数字见 M6 记录。

## 实测边界

只读历史不访问官方浏览器；历史中缺失的官方状态或核对时间不推测。真实账号的订单页面、支付和候补兑现没有由离线夹具证明；发布前需在受控真实环境人工核查。候补生效后的定时复查留待后续版本。
