# v0.4.2 P1 审查问题修复记录

日期：2026-09-24。范围：本轮代码审查的 R1、R2、R3。基于当前 v0.4.2 工作区继续修改，保留既有实施改动；本轮没有构建安装包或发布资产。

## R1：查询不再覆盖正式配置

移除 `RailWatchBridge.analyze_query()` 对 `save_config()` 的调用。查询消费本次请求配置，正式行程、草稿及最近路线文件不因查询而改变。

`tests/test_query_snapshots.py` 增加六种组合：指定另一目标／查询全部车次，分别覆盖查询成功、查询失败、浏览器初始化失败。断言正式配置、草稿和最近路线文件的内容及修改时间保持不变，原目标和可恢复草稿仍可读回。

## R2：运行结果按当前草稿校验和应用

`MonitorPage` 使用草稿作为结果选择的路线和日期校验对象，使用草稿中已有车次作为合并起点，保留草稿优先级；运行任务快照保持独立。点击应用前再次从 store 读取当前修订与结果，拒绝已变化或不属于草稿路线的选择。

`QueryResults` 在草稿条件或可选车次集合变化时清除旧勾选；不匹配结果给出说明，结果消失后不再允许应用旧选择。相关路线／日期匹配逻辑集中在 `src/lib/queryResults.ts`。

新增组件回归覆盖不同路线草稿保护、同路线草稿车次合并、路线／日期切换时相同车次的旧勾选清理及结果清空。

## R3：运行时故障下可明确选择强制退出

正常退出继续执行活动检查、用户确认、草稿收尾及后端停止流程。运行时请求失败、超时或后端停止未完成时，提供“取消／强制退出”，默认取消，明确提示状态未知、未保存草稿风险和官方订单核对要求。

用户明确选择强制退出后，清理提醒和确认请求、阻止运行时重启；Windows 上通过当前持有的运行时 PID 清理其进程树，清理命令有五秒超时，不按进程名称批量结束 Chrome。运行时已经退出时，不使用旧 PID 清理；可能已脱离运行时的浏览器需用户关闭。订单数据库不被删除或改写。本次未放宽安装更新门禁。

新增主进程回归覆盖正常退出、活动任务取消、故障取消后再次退出、停止超时及重复退出请求；运行时回归覆盖限定 PID 的进程树清理、清理失败兜底、崩溃后的重启取消及退出期间请求拒绝。
