# v0.5.5：多日期策略、多组合候补与持续订单核对

应用、Python 运行时、Windows 安装包及自动更新版本统一为 0.5.5。

## 本次更新

- **多日期策略**：选择多日范围后，可选「按日期顺序尽快候补」（默认，保留旧行为）、「先查首选日期」或「限时扫描多日期现票」。限时扫描默认预算 30 秒（可设 10～120 秒），扫描结束后重新查询并核对候补入口，不复用旧页面按钮。定时起售窗口（默认起售后 45 秒）内仍只查询所选日期。
- **多组合候补（实验性）**：在「行程设置 → 自动化」切换为「多个已配置组合」后，通过官方「添加备选方案」选择已配置的车次、席别与最多 3 个日期内的组合，上限 1～60。完整清单先保存到本地订单意图再提交，最终提交前逐项回读；出现额外组合或身份不明时停止提交。订单中心显示实际保存的组合。
- **持续订单核对**：取得匹配订单号后，按设置间隔（默认 60 秒，可设 30～600 秒）在临时标签页核对原订单，保留付款页面；读取失败逐步放慢，不会覆盖最后确认状态。可在订单中心停止，或在重启后点击继续核对。
- **定时起售优化**：首轮日期与查询表单在等待起售前准备好；查询前的表单读取、弹窗检查和响应监听合并为一次浏览器命令；唤醒诊断改为延后批量写盘；自动提交或自动候补任务在起售前 10～60 秒确认一次登录状态，最后 10 秒不做登录探测。
- **失败组合暂避**：已确认售罄或候补入口不可用的车次席别暂避 30 秒，继续检查其他目标。受控浏览器被关闭后停止监控并提示重新打开登录页。
- **运行复盘**：新增最近最多 200 轮查询的分阶段耗时（中位数、P95）及同一日期两次查询的实际间隔。
- **更新安装**：Windows 更新改为确认安装程序已启动（含提权）后再退出；启动失败时恢复后台可用状态并提示原因。活动任务或未完成订单仍会阻止安装。

## 下载与升级

Windows 10/11 用户下载本页 Assets 中的 `RailWatch-12306-0.5.5-x64.exe`，或使用应用内检查更新。安装包内置 Python 运行时，仍需安装 Google Chrome。旧配置升级后保持原有日期顺序和单组合候补，多日期策略与多组合候补需在设置中手动开启；持续订单核对默认开启，可在自动化设置中关闭。

## 验证与使用边界

发布前本地验证通过：Python 单元测试 464 项（pytest 计 478 项及 254 个子测试）、Electron 测试 93 项、前端测试 260 项，类型检查及生产构建通过。隔离浏览器测试：查询 31 项、订单 62 项、多组合候补 17 项通过；定时冒烟与冻结运行时多组合恢复冒烟通过。

多组合候补与持续核对基于本地页面夹具和公开页面模板验证，尚未完成真实账号的候补创建、预付款至兑现的完整现场验收。自动候补仍为实验性功能；登录核验和支付由用户在官方页面完成，实际订单状态以官方页面为准。详细说明见 [多日期查询与性能说明](https://github.com/shyrel666/RailWatch-12306/blob/v0.5.5/docs/efficiency-phase1.md) 与 [多组合候补与持续订单核对](https://github.com/shyrel666/RailWatch-12306/blob/v0.5.5/docs/efficiency-phase2.md)。
