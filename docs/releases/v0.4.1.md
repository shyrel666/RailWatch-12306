# RailWatch 12306 v0.4.1

本版本集中修复订单证据误判、运行时状态竞态、查询循环落库开销及本地配置安全问题。

## 更新内容

- **订单证据**：纯数字车次只接受结构化字段或带“次”的明确车次标记，避免票价等普通数字被误当成目标车次。
- **状态一致性**：后台健康信息晚到时不再覆盖更新的监控事件，任务、序列、查询结果和命中状态保持一致。
- **查询性能**：高频查询遥测批量写入 SQLite 并限制保留量；提交意图、提交标记和订单结果仍使用即时事务保存。
- **配置可靠性**：配置和偏好采用原子替换写入，磁盘写入失败不会破坏上一份有效文件，配置读取失败会记录明确告警。
- **凭据保护**：Server 酱、邮件和企业微信凭据在 Windows 上使用当前用户 DPAPI 加密保存，返回 Electron 渲染进程前统一脱敏；旧明文配置首次读取后自动迁移。

## 下载与升级

下载本页附件 `RailWatch-12306-0.4.1-x64.exe`，退出旧版后安装；也可使用应用内检查更新。`latest.yml` 和 `.blockmap` 附件供自动更新使用。

## 验证范围

完成 Python、Electron、React、TypeScript、离线 Chrome 查询与订单流程回归，以及打包运行时启动和 SQLite 订单恢复检查。新增覆盖纯数字车次与票价冲突、运行时旧快照、遥测批处理与上限、原子写入失败、DPAPI 往返和渲染层脱敏。

自动化测试未执行真实账号下单或支付。核验及支付仍需在官方页面人工完成，实际订单状态以 12306 为准。
