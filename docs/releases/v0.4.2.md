# RailWatch 12306 v0.4.2

本版本改善查询结果、桌面任务生命周期、通知、行程配置和订单历史，并修复订单提交证据与运行时恢复问题。

## 更新内容

- **查询结果**：按日期和实际区间展示车次、时间、席别与采集时间；查询失败保留并标记上一份成功结果。
- **后台与更新**：可选择关闭到托盘；退出和安装更新前检查活动任务与未完成订单，订单记录可留待重启后核对。
- **通知**：桌面、声音、置顶及邮件、Server 酱、企业微信渠道可配置和试发，展示各渠道反馈；外部凭据由本机用户的 Windows DPAPI 保护。
- **行程**：站名联想、最近路线、路线车次收藏和实际查询结果选车次；席别按已验证能力展示。独立草稿可恢复，启动前可核对本次任务条件。
- **订单中心**：查看历史、已有事件、最后已确认的官方状态与本地观察状态，并继续核对原订单。
- **可靠性修复**：合并订单的可见车次证据，拒绝冲突；修复 DPAPI 异常恢复及原子写入故障清理。
- **交易保护**：确认点击回执未知时保留当前页面，不重复确认；提交后空订单列表不再视为未创建订单，继续保留未决订单保护。
- **查询与确认**：快照失效时有界重新读取，持续失效明确提示；主进程统一发起启动摘要，确认期间行程变化会拒绝启动。
- **恢复与状态**：运行时有限退避重启、就绪握手和手动重试；坏协议行隔离、人工提示恢复、订单观察退避，以及历史显示截断提示。
- **发行与文档**：补齐 Python 起售时间模块，更新行程设置、购票监控和订单中心截图。

## 下载与升级

Windows 10/11 用户下载下方的 `RailWatch-12306-0.4.2-x64.exe` 安装包；`.blockmap` 和 `latest.yml` 用于应用内更新，无需手动安装。需要本机已安装 Google Chrome，安装包内置 Python 运行时。

升级保留旧配置、偏好、通知凭据和订单库；草稿与路线收藏是独立文件，恢复草稿不会启动交易。

## 支持边界

自动提交与自动候补默认关闭。程序只对明确支持的成人乘客和席别组合尝试自动交易，提交前仍需官方页面回读；学生、儿童票种请在官方页面处理。乘客读取仅扫描当前受控浏览器页面可见的候选，不能遍历完整乘客管理资料。普通订单列表只显示姓名时，可按完整姓名唯一勾选，再回读对应乘客行的成人票种；同名或最终票种无法确认时停止自动化。候补仍要求列表明确标为成人。

自动候补仍为实验性功能；候补生效后不会周期性自动复查，订单中心提供主动继续核对入口。支付后的状态同步、候补提交至兑现、断网及重启恢复仍待完整真实场景验收，本地离线回归不能代替这些验收。登录核验与支付须在官方页面完成，实际订单状态以 12306 为准。
