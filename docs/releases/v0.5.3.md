# v0.5.3：交易核对、彩排与行程恢复修复

应用、Python 运行时、Windows 安装包及自动更新版本统一为 0.5.3。

## 本次更新

- 修复候补页成人票种、自定义乘客勾选和待支付倒计时的识别；订单号、日期、区间、席别与乘客仍需完整匹配。
- 停止后不再触发新的确认点击；已尝试提交但结果未知时保存待核对记录，避免重复提交。
- 已绑定订单号可在普通订单与候补历史标签中有限查找；尚未绑定的提交不能用历史订单解除拦截。
- 彩排不再把缺失的本人票种或无法判断的时钟结果当作通过。定时仍使用系统时钟，HTTP 时间只用于辅助诊断。
- 读取乘车人自动在临时标签页打开官方列表，最多读取 10 页／100 人，完成后恢复原页面；名单不完整时提示重试。
- 运行复盘新增下单页加载、选择乘客与席别、提交前核对的分步耗时，并修复并发事件记录的顺序。
- 修复界面重载后的草稿恢复、慢命令期间的停止响应与并发环境检查；更新 README 界面截图。

## 下载与升级

Windows 10/11 用户下载本页 Assets 中的 `RailWatch-12306-0.5.3-x64.exe`，或使用应用内检查更新。安装包内置 Python 运行时，仍需安装 Google Chrome。

## 验证与使用边界

发布前本地验证通过：Python 单元测试 389 项、Electron 测试 79 项、前端测试 250 项，类型检查及生产构建通过。查询、订单、乘车人与彩排的隔离浏览器测试共 98 项通过，彩排／复盘、查询、通知、行程／订单四组界面检查通过。README 三张截图使用隔离演示数据。

已完成的真实有效登录只读彩排没有创建、支付或取消订单；乘车人票种和时钟证据不足时总结论保留“有风险”。详细证据见 [真实页面审查修复记录](https://github.com/shyrel666/RailWatch-12306/blob/v0.5.3/docs/live-review-fixes-2026-09-29.md)。

自动候补仍为实验性功能。真实候补创建、预付款至兑现、支付后的完整状态同步及断网／重启恢复仍待完整现场验收。登录核验和支付由用户在官方页面完成，实际订单状态以官方页面为准。
