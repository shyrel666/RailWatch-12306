# v0.4.2 M1 完成与验证记录

日期：2026-09-22。范围：C1 结构化查询结果与数据时效；M2–M6 尚未实施。

## 1. 实现结果

- 后端从同一次批量 DOM 读取中生成公开结果，保留车次、查询日期、实际区间、可确认的时刻与到达日、席别状态／数量和原始文字。公开结果不含 WebElement 或席别列索引；交易匹配继续使用原快照。
- 余票仅从对应席别单元格解析，支持数字、“有”、“无”、“候补”；不明确的 `--`、`*` 和缺字段显示未知。整行“张家界”“无座”等文字不能改变席别状态。
- 手动查询和监控使用同一 `QuerySnapshot`；`queryStarted` 标明当前查询日期。监控成功结果在最后一次查询有效性检查通过后发布，HTTP 等待、超时或条件失效先发布失败状态。
- 前端按路线、日期、目标车次／席别保存最新尝试及上次成功快照。同车次不同日期分别显示；失败保留旧结果，成功空列表只清除对应日期。
- 任务 ID、手动请求 ID、查询序号及条件共同约束归属。运行中编辑使用既有任务快照；未运行时改查询条件会清空旧视图；新任务、超时后到达的手动响应及迟到旧事件不能覆盖当前结果。
- 界面展示已选席别、明确状态文字、北京时间采集时间及原始信息展开区。缺少结构化字段的旧事件显示状态／时间未知，不回退到整行关键字推断。

主要文件：`railwatch_row_parser.py`、`railwatch_query.py`、`gui_12306_0.py`、`railwatch_bridge.py`、`railwatch_runtime.py`、`src/lib/queryResults.ts`、`src/store/railwatchStore.ts`、`src/components/QueryResults.tsx`、`src/components/MonitorPage.tsx`、`src/App.tsx`、`src/types.ts`、`src/styles/pages.css`。

## 2. 时效和失败语义

- 每个日期单独保留 `fetched_at`；失败快照为 `null`，不会拿失败时间冒充刷新成功。
- 日期范围天数 ×（查询超时 + 配置间隔）+ 5 秒为展示过期阈值；服务端要求等待时仍保留原阈值，显示下一次查询倒计时，避免长退避使旧余票看起来更新。
- 失败、人工处理／暂停、停止、等待和过期有不同文字；保留结果始终标为最近或上次成功结果。
- 手动多日查询沿用串行浏览器操作。部分日期失败时返回此前成功日期及本次失败日期，结束剩余日期查询；未执行日期不伪造新快照。
- 旧数据只保存在内存，不增加持久化查询历史。应用版本仍为 0.4.1，版本号与安装包按计划在 M6 处理。
