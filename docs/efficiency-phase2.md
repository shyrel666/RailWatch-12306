# 第二批：多组合候补与持续订单核对

更新：2026-10-04。本文描述当前源码；已有安装包不会因源码变更自动更新。

## 使用方式

在「行程设置 → 自动化」选择候补组合模式，设置组合上限和订单核对间隔，然后保存配置。多组合设置不会自动开启自动提交或候补排队，原有交易授权开关仍需单独设置。

| 设置 | 默认值 | 可选范围与含义 |
| --- | --- | --- |
| 候补组合 | 首个可用组合 | 可切换为「多个已配置组合」 |
| 候补组合上限 | 5 | 1～60个日期／车次／区间／席别组合，最多3个日期 |
| 持续订单核对 | 开启 | 取得匹配订单号后持续核对，可关闭 |
| 订单核对间隔 | 60秒 | 30～600秒；每轮核对结束后等待，实际周期还包含页面加载时间 |

例如配置两个车次和三个日期，多组合模式会从实际命中的组合开始，在官方页面选择配置范围内可用的备选，最多达到设置上限。上限是容量限制，不保证每次都能选满。当前自动候补已开放的席别仍只有二等座；本次没有扩展席别能力，也不会添加未配置的车次、同城不同车站、无座或「接受新增列车」。

「订单中心」展示实际保存的完整组合、最后确认的官方状态、最近核对时间、下次核对时间和异常退避说明。可点击「停止本地核对」，停止后通过「继续核对」恢复；停止本地任务不会取消官方候补。应用退出或重启后保留订单，需点击继续核对。

## 多组合的选择与提交

1. 查询页只进入首个目标组合的候补表单。当前查询页选择后会自动跳转，因此多个备选通过订单表单内的官方「添加备选方案」选择。
2. 固定当前任务的可用日期集，先保留首个命中组合，再按日期、配置车次和席别顺序选择。最多三个日期；定时起售集中查询窗口及明确售罄后的候补回退仍只使用原订单日期。
3. 只点击可见、可操作的原生页面控件。切换日期须确认结果区域已重新渲染，车次、车站、席别等字段一致。日期查询与重新打开编辑器沿用配置间隔，同时遵守请求模式下限。
4. 沿用跨日期扫描预算限制继续扫描其他日期；达到上限或预算后，对已经选中的完整清单继续核验。预算不截断正在执行的官方操作，也不跳过核验。
5. 逐日期回读每个具体组合及各日期数量，不能用独立的「车次集合」「日期集合」拼出未选择的交叉组合。选满三日期或容量后，添加入口消失时可通过已有方案的编辑入口复核。
6. 将确切清单原子写入本地订单意图，再选择乘客、截止时间并重新回读全部组合。出现额外组合、组合改变、身份不明或保存失败时停止提交。最终提交前仍先保存提交标记，按钮只点击一次。

页面原生控件会发起官方请求；本地没有调用网页私有下单函数或并发提交多个候补单。支持一份候补订单覆盖多个可接受方案，仍保留一个未解决订单的本地互斥限制。

## 持续核对与状态依据

- 待支付时，保留当前页面并做只读观察：开始10秒内约每秒读取，随后约每5秒，60秒后约每15秒；这些读取不刷新页面。达到订单核对间隔后，在临时独立标签页查询已绑定订单，完成后关闭该标签页并返回原标签页。
- 候补生效后继续按设置间隔核对，不再到生效状态或10分钟就结束。每轮只查原订单及相关官方列表标签，不翻页、不改变筛选日期、不支付、不取消、不重建候补。
- 匹配必须同时满足订单号、订单种类、完整乘客名单和精确组合。兑现后页面只展示最终组合时，必须已有相同候补单号、明确的兑现成功状态，且该组合在持久化清单中。
- 官网待支付、待兑现卡片可能只显示首项。初次取得订单证据或在临时标签页核对时，点击该订单卡片内的「候补明细」，逐项读取完整清单，关闭明细后再次确认单号和乘客。已有未知弹窗时不会打开明细，也不借用其他订单的详情；付款期间的常规页面读取不反复打开明细。
- 未找到匹配记录、页面读取失败或网络异常不会覆盖最后确认状态。失败后逐步放慢，默认等待120、240、480秒，最高600秒；成功取得证据后恢复配置间隔。旧的待支付页面不能使已生效候补倒退为待支付。
- 登录或人工核验出现时暂停并提示处理，保留原单号。已确认的兑现、取消、过期或失败结束核对，并释放本地订单锁。已有的支付、生效和兑现提醒仅在状态变化时触发，未变化的轮询不会重复通知。
- 停止请求可中断等待；临时标签页的清理与恢复原标签页会完成。驱动命令本身仍受原有传输超时约束，不能保证卡住的驱动立即返回。

关闭持续核对时保留旧的付款页短时观察：最多10分钟，候补生效后结束本地观察；官方队列继续运行。未取得订单号时不会开启自动历史探测，仍按原流程要求核对未知提交结果。

## 持久化与恢复

新增策略表 `railwatch_policies/order_policies.json`，由前端、后端共享，并进入 wheel 和冻结运行时。配置经过校验、保存、草稿、任务快照和运行时恢复传递。

`OrderIntent.choices` 保存完整日期／车次／车站／席别组合，兼容旧的单组合记录。`alternate_choices` 事件记录清单保存时点，分步耗时新增「选择候补组合」。不保存网页密钥、完整页面或支付资料。

提交标记或恢复认领存在后，禁止重新绑定组合。重启不会启动浏览器或重放提交；已有订单只核对原单。没有提交标记的表单恢复仍必须重新核验已保存清单，不能把页面上未经持久化的额外选择自动接纳为授权。

## 官方页面依据与验收边界

2026-10-04通过公开 GET 页面核查了当前官方表单与脚本：订单表单备选编辑器注明最多三个日期、60个候补车次；查询页仍有旧购物车结构，因此不能把旧入口当成多组合编辑器。当前实现以日期／车次／区间／席别组合计数，上限比跨席别合并车次计数更严格。

公开页面核查没有使用真实账号，也未提交订单。Chrome回归使用合成数据和独立浏览器配置，阻断12306网络。多组合候补提交、支付后生效、真实兑现和登录后页面变体仍需实际场景验收；离线通过不代表购票成功率得到实测提升。
