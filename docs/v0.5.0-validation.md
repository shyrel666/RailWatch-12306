## 真实会话只读联调

使用 `scripts/validate_rehearsal_live.py` 附加当时空闲的受控浏览器，新建专用标签页并使用临时设置／订单库。执行前检查原库没有未决订单且近期没有任务提交或查询活动；测试结束恢复原标签页及 URL，关闭自己的 ChromeDriver 连接，保留原浏览器。

观测耗时 **6.06 秒**：

| 检查 | 结果 |
| --- | --- |
| 配置／官方起售时刻／浏览器 | 通过 |
| 登录 | 失效，报告明确要求重新登录 |
| 乘车人／车次席别／交易演练 | 因登录依赖失败而跳过 |
| HTTP 时间辅助检查 | 无法判断，未冒充系统已校准 |
| 本机唤醒／提醒配置 | 通过，未发送外部提醒 |
| 总结论 | 会失败（登录失效） |

临时 `orders`、`order_events` 均为零，原应用两表计数未改变，报告未包含配置中的完整姓名。没有点击官方交易按钮，没有创建订单，没有修改账号、正式行程或已有订单。

此现场结果验证了**登录失效保护路径**；不能标记为“已登录完整彩排通过”。当时 M0 读到的官方页面结构仍有此前证据，但不能据此断言本次会话有效。

## 实现取舍与待验收

- 自动彩排发布时默认关闭，保留用户已显式开启的偏好；试发提醒默认关闭。复盘导出未新增，符合方案的可选项范围。
- 历史报告不持久化含姓名的行程指纹，重启加载后保守提示过期。内存中的报告与当前草稿按原有 `tripFingerprint` 比较。
- 本人缺少明确票种时，普通订单预检警告、候补预检失败；“预通过／待核验”不统一认定为官方拒绝购票。
- 本地演练不能证明官方交易 DOM 没有变化，也不表示下单成功。实际官方处理段是本机观察时间，不能作为服务器承诺。
- 正常轮询和离线取消已测；同步 WebDriver 命令若遇驱动卡死，仍受底层超时约束。尚未把“所有故障场景一秒释放”或“所有环境六十秒完成”标为通过。
- 重新登录后，应补验一次真实的乘车人读取、单次查询与完整报告，核对耗时、脱敏和零新增交易；若账号本人票种未知或日期运行图存在差异，应保留真实风险结论，不为验收强行改成“就绪”。
- 发布安装包前需按 [发布清单](RELEASE_CHECKLIST.md) 验证打包运行时与安装包；本次没有发布、安装或替换正在运行的用户应用。
